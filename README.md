
# 研究工程

这是研究生产系统的工程仓库。

仓库的目的不是堆放所有研究材料，也不是一次性写完一套方法论，而是把研究系统放进真实项目中运行，用项目暴露问题，再把经过验证的经验沉淀回系统。

## 仓库结构

当前只保留三个主要内容层：

```
系统/
理论资产/
项目/
```

### 系统

保存当前正在使用的正式研究系统。

目前包括：

- 问题图系统
- 当前基线

其中 `系统/问题图/` 保存当前正式的 00–06 文件。

### 理论资产

保存尚未进入正式系统的理论研究、概念推演和设计实验。

目前的主要理论资产是：

`理论资产/问题主题/`

它讨论“问题是什么、问题如何闭合、问题图应如何理解”等更基础的问题，必须经过真实项目验证后，才考虑进入正式系统。

本阶段新增理论资产：

`理论资产/问题主题/认知—问题图—研究—商业表达.md`

该资产进一步讨论“认知模型、问题图、读厚、读薄、Business Writing 与研究交付之间的关系”，目前仅作为理论假说保存，暂不进入正式规约。

### 项目

保存研究系统实际运行的项目实例。

目前第一条运行验收线路是：

`项目/CQD短波红外/`

## 版本

仓库不单独设置“版本”目录。

系统、理论和项目的修改历史由 Git 保存。某个时间点需要形成完整发布包时，再从对应提交导出，而不是在仓库中长期维护重复副本。

## 当前运行线路

第一条验收线路：

```
材料进入 → 问题展开 → 形成判断 → 制作交付 → 检查修订 → 版本固定
```

目标不是证明理论正确，而是检查研究系统能否在真实任务中稳定运行。

## 当前原则

1. 先运行，再补结构。
2. 未经真实项目验证的理论，不进入正式系统。
3. 项目经验首先属于项目，不自动升级为通用规则。
4. Git 保存修改历史，仓库目录只表达当前对象的性质。
5. 只有真正需要长期复用的内容，才沉淀为系统资产。
