# 研究工程

这是个人研究生产系统的工程仓库。目标不是堆放研究材料，而是把研究方法放进真实项目中运行，用项目暴露问题，再把经过验证的经验沉淀为可复用资产。

## 仓库结构

```
BOOT.md          # 冷启动入口：启动顺序、执行边界与状态回写
SYSTEM/          # 正式规约与理论资产，按需加载
templates/       # 项目运行态模板
skills/          # 经实战验证后沉淀的可复用研究技能
projects/        # 真实研究项目、证据与当前状态
```

### BOOT.md

跨模型、新会话或没有历史对话上下文时，先读取根目录 `BOOT.md`。它负责启动和调度，不替代正式系统规约。

### SYSTEM/

- `SYSTEM/00-06/`：当前正式问题图规约。默认不批量读取，按 `SYSTEM/INDEX.md` 路由。
- `SYSTEM/THEORY/`：尚未升级为正式规约的理论研究和设计探索，默认不参与日常启动。
- `SYSTEM/当前基线.md`：记录系统当前所处阶段与验证边界。

### templates/

保存新项目初始化时复制的 `graph.yaml`、`memory.md` 等最小模板。项目运行时文件是各项目自己的状态，不与模板同步记账。

### skills/

只保存经过真实项目验证、边界和触发条件明确的可复用研究动作。未验证的方法先留在项目或理论资产中，不提前扩张技能库。

### projects/

保存真实研究项目。当前已有：

- `projects/CQD短波红外/`

每个项目维护自己的问题图、负知识和证据材料。项目经验首先属于项目，不自动升级为系统规则。

## 当前原则

1. 先运行，再补结构。
2. 问题图管理研究状态，不直接充当最终报告目录。
3. 证据可追溯，判断可修正，负知识可重新打开。
4. Git 保存版本历史；不在仓库中复制多份当前规约。
5. 只有真正需要长期复用且经过验证的内容，才沉淀为系统资产。
