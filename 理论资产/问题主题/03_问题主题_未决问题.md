# 问题主题：未决问题

## 1. 用途

本文件专门保存目前尚未解决、但值得继续研究的问题。

原则：**不为了“完整”而提前给出答案。**

## 2. 问题的边界

### 2.1 问题与任务如何区分？

- “研究 CQD”显然更接近任务。
- “CQD 能否形成成本优势？”显然更接近问题。
- 二者之间的边界如何形式化？

### 2.2 问题与假设如何区分？

例如：

- “CQD 可以显著降低 SWIR 成本。”——可能是假设。
- “CQD 是否可以显著降低 SWIR 成本？”——是问题。

需要定义二者的状态转换关系。

### 2.3 问题与命题如何区分？

问题要求确定某件事；命题是可被判断真假的内容。二者如何在系统中对应，尚需进一步明确。

### 2.4 问题与判断标准如何区分？

例如：

> 成本下降 50% 才具有商业意义。

这是问题的一部分、判断标准，还是研究实现中的外部约束？

## 3. 闭合问题

### 3.1 什么叫“问题闭合”？

是获得一个答案即可闭合，还是必须达到一定证据质量、反证排除程度或决策置信度？

### 3.2 谁决定闭合？

可能是：

- 研究者
- 项目负责人
- 决策者
- 预设规则
- Agent

这些角色之间如何分工？

### 3.3 闭合是否可以分级？

例如：

```
未开始
部分闭合
当前可接受
高置信度
重新打开
```

是否需要这样的状态体系，尚未决定。

## 4. 问题身份与重构

### 4.1 什么时候还是“同一个问题”？

研究过程中经常会发生语言变化、范围缩小、变量变化。

需要判断：

> 什么程度的修改属于问题演化，什么程度已经构成新问题？

### 4.2 前提失效后的问题如何处理？

需要区分：

- 原问题继续存在，但答案改变；
- 原问题暂时失效；
- 原问题被新问题取代；
- 原问题拆分成多个问题。

## 5. 证据与判断

### 5.1 Evidence、Claim、Judgment 是否真的需要三层？

目前看有价值，但尚未用多个案例验证。

### 5.2 同一证据服务多个问题时，如何记录语义？

需要定义证据与问题、假设、判断之间的关系类型。

### 5.3 证据冲突如何表达？

例如：

```
来源 A → 支持
来源 B → 反驳
```

系统需要能表达冲突，而不是简单做平均。

## 6. 问题图结构

### 6.1 认知依赖是否存在不同类型？

候选包括：

- 前置事实依赖
- 因果解释依赖
- 定义依赖
- 阈值依赖
- 反证依赖
- 决策依赖

目前不应急于建立完整分类表。

### 6.2 是否需要方向之外的关系信息？

例如：

- 必要 / 非必要
- 强依赖 / 弱依赖
- 可替代路径
- 条件依赖

待真实案例检验。

### 6.3 问题图与知识图谱如何连接？

可能的方向是：

```
问题图
  ↓ 调取
知识 / 证据
  ↓ 形成
判断
  ↓ 沉淀
知识图谱
```

但二者的边界和同步机制尚未定义。

## 7. Agent 执行

### 7.1 Agent 是否应该先识别问题，再执行研究？

需要验证：

> 自然语言任务 → 问题对象 → 研究实现 → 工具调用

是否比“直接要求 Agent 写报告”更稳定。

### 7.2 Agent 能否自动判断问题未闭合？

这是一个核心能力问题，暂不假定可以自动化。

### 7.3 Agent 发现新问题时，谁有权修改原问题图？

需要明确人机协作边界。

## 8. 最重要的验证案例

优先用一个真实硬科技投资研究案例验证完整链条，而不是继续做抽象推演。

建议测试对象：

> **CQD 是否能够凭借工艺优势，把 SWIR 传感器成本降低到足以打开新的机器视觉市场？**

测试内容：

```
问题识别
→ 问题拆解
→ 认知依赖
→ 研究实现
→ 证据进入
→ 判断形成
→ 新证据反驳
→ 图结构回溯
→ 当前闭合 / 重新打开
```

## 9. 当前原则

> **未验证的概念，不进入正式规范；未解决的问题，不强行给出结论。**
