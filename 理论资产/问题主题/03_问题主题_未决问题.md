# 问题主题：未决问题

## 1. 用途

本文件专门保存目前尚未解决、但值得继续研究的问题。

原则：**不为了“完整”而提前给出答案。**

## 2. 问题的边界

### 2.1 问题与任务如何区分？

- “研究 CQD”显然更接近任务。
- “CQD 能否形成成本优势？”显然更接近问题。
- 二者之间的边界如何形式化？

### 2.2 问题与假设如何区分？

例如：

- “CQD 可以显著降低 SWIR 成本。”——可能是假设。
- “CQD 是否可以显著降低 SWIR 成本？”——是问题。

需要定义二者的状态转换关系。

### 2.3 问题与命题如何区分？

问题要求确定某件事；命题是可被判断真假的内容。二者如何在系统中对应，尚需进一步明确。

### 2.4 问题与判断标准如何区分？

例如：

> 成本下降 50% 才具有商业意义。

这是问题的一部分、判断标准，还是研究实现中的外部约束？

## 3. 闭合问题

### 3.1 什么叫“问题闭合”？

是获得一个答案即可闭合，还是必须达到一定证据质量、反证排除程度或决策置信度？

### 3.2 谁决定闭合？

可能是：

- 研究者
- 项目负责人
- 决策者
- 预设规则
- Agent

这些角色之间如何分工？

### 3.3 闭合是否可以分级？

例如：

```
未开始
部分闭合
当前可接受
高置信度
重新打开
```

是否需要这样的状态体系，尚未决定。

## 4. 问题身份与重构

### 4.1 什么时候还是“同一个问题”？

研究过程中经常会发生语言变化、范围缩小、变量变化。

需要判断：

> 什么程度的修改属于问题演化，什么程度已经构成新问题？

### 4.2 前提失效后的问题如何处理？

需要区分：

- 原问题继续存在，但答案改变；
- 原问题暂时失效；
- 原问题被新问题取代；
- 原问题拆分成多个问题。

## 5. 证据与判断

### 5.1 Evidence、Claim、Judgment 是否真的需要三层？

目前看有价值，但尚未用多个案例验证。

### 5.2 同一证据服务多个问题时，如何记录语义？

需要定义证据与问题、假设、判断之间的关系类型。

### 5.3 证据冲突如何表达？

例如：

```
来源 A → 支持
来源 B → 反驳
```

系统需要能表达冲突，而不是简单做平均。

## 6. 问题图结构

### 6.1 认知依赖是否存在不同类型？

候选包括：

- 前置事实依赖
- 因果解释依赖
- 定义依赖
- 阈值依赖
- 反证依赖
- 决策依赖

目前不应急于建立完整分类表。

### 6.2 是否需要方向之外的关系信息？

例如：

- 必要 / 非必要
- 强依赖 / 弱依赖
- 可替代路径
- 条件依赖

待真实案例检验。

### 6.3 问题图与知识图谱如何连接？

可能的方向是：

```
问题图
  ↓ 调取
知识 / 证据
  ↓ 形成
判断
  ↓ 沉淀
知识图谱
```

但二者的边界和同步机制尚未定义。

## 7. Agent 执行

### 7.1 Agent 是否应该先识别问题，再执行研究？

需要验证：

> 自然语言任务 → 问题对象 → 研究实现 → 工具调用

是否比“直接要求 Agent 写报告”更稳定。

### 7.2 Agent 能否自动判断问题未闭合？

这是一个核心能力问题，暂不假定可以自动化。

### 7.3 Agent 发现新问题时，谁有权修改原问题图？

需要明确人机协作边界。

## 8. 最重要的验证案例

优先用一个真实硬科技投资研究案例验证完整链条，而不是继续做抽象推演。

建议测试对象：

> **CQD 是否能够凭借工艺优势，把 SWIR 传感器成本降低到足以打开新的机器视觉市场？**

测试内容：

```
问题识别
→ 问题拆解
→ 认知依赖
→ 研究实现
→ 证据进入
→ 判断形成
→ 新证据反驳
→ 图结构回溯
→ 当前闭合 / 重新打开
```

## 9. 当前原则

> **未验证的概念，不进入正式规范；未解决的问题，不强行给出结论。**


## 10. 本轮新增的未决问题

### 10.1 如何识别“我真正想问的是什么”？

需要区分：

- 人最初表达出来的问题；
- AI根据上下文推测的问题；
- 人最终认领的问题。

一个重要验收标准可能是：

> 问题形成完成后，人是否能够明确说出“这才是我真正想知道的”。

### 10.2 AI的澄清会不会偷换人的问题？

AI可能把人的模糊兴趣收束成一个更容易回答、但并非本人真正关心的问题。需要研究如何识别这种“问题漂移”。

### 10.3 问题形成和问题生成如何区分？

“生成问题”可能只是扩大候选空间；“澄清思考”则是从人的实际认知状态中找到真正值得研究的问题。二者是否应由不同的系统动作承担，尚未确定。

### 10.4 AI扩展问题是否真的提高研究质量？

需要与“直接生成研究框架”做真实对比，而不能只看生成问题数量。

### 10.5 谁决定一个问题值得进入现实？

候选问题可能很多，但现实提问存在时间、关系、信息暴露和信誉成本。需要明确人和AI在这一选择上的边界。

### 10.6 现实回答如何回流问题图？

需要验证“AI问题沙盒 → 现实提问 → 现实回答 → 带回AI → 继续追问 → 问题图更新”这一闭环是否比单向问答更有价值。

### 10.7 “提问品味”能否被观察和描述？

目前只是一个工作概念，可能包含问题是否必要、是否抓住关键变量、是否与当前情境匹配、是否体现对对方处境的理解等。暂不建立分数体系。

### 10.8 问题本身是否应成为可沉淀的能力资产？

例如长期记录：什么人问过什么问题；什么问题后来被证明重要；哪些问题反复出现；哪些问题最终没有价值。这可能决定问题图只是研究工具，还是长期认知资产。

### 10.9 问题、答案、判断与投资判断资产如何区分？

当前工作区分是：

```text
问题
↓
答案
↓
判断
↓
投资判断资产
```

还需要真实项目验证它们分别在哪个环节形成，以及投资判断资产与立项、投决、投后文书之间的关系。
