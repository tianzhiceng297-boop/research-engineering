# 四出口商业交付协议

## 用途与触发条件
当研究任务需要形成投资判断、内部决策备忘录、投资经理汇报或正式商业交付时调用。纯技术求真、产业机制探索和一般事实查询不强制套用四出口。

最终决策必须明确归入以下一个出口：
- **做（Go）**：风险收益与行动条件支持推进。
- **等触发（Watch）**：方向可能成立，但价格、时点、证据或里程碑尚未满足。
- **换道（Pivot）**：原路径的关键前提不成立，但邻近环节、替代路线或不同交易结构仍有价值。
- **不做（Pass）**：关键前提被证伪，或预期回报不足以补偿风险与机会成本。

不得为了显得积极而回避 Pass，也不得把所有不确定性都写成 Watch。

## 通用交付结构
1. **决策出口**：Go / Watch / Pivot / Pass，只选一个主出口；必要时说明次级观察方向。
2. **核心判断**：直接说明结论、强度与时间边界。
3. **判断链条**：关键事实 → 因果机制 → 经济结果 → 估值/投资含义。
4. **证据与反证**：列明最重要的一手证据、相反证据、证据质量和信源偏差。
5. **成立条件与失效条件**：区分可验证条件、外部条件和关键假设。
6. **下一步动作**：明确是研究、访谈、代码验证、等待触发还是停止投入。

## Go / Watch 的额外要求
- **赔率与安全边际**：说明当前价格隐含了什么、合理情景范围、潜在回报和下行风险；无法量化时解释缺失数据。
- **成立条件**：列出真正承重的 1–3 个前提及其验证方式。
- **Pre-mortem（事先验尸）**：假设投资最终失败，找出最可能的一项脆弱性及传导机制。
- **仓位上限**：结合证据置信度、流动性、波动、相关性和单点风险给出约束；没有组合信息时不擅自给精确仓位。
- **止损/重评红线**：给出可观察、可执行的事实触发器，不用模糊情绪阈值。

Watch 还必须写清：当前为何不行动、等待什么事件/价格/证据、触发后谁负责复核。仅写在 memory 等待雷达不代表已经配置自动提醒。

## Pivot 的额外要求
- 明确原路线被什么证据或机制削弱；
- 说明替代路线解决了原路线的哪个约束；
- 比较替代路线的成本、客户、竞争、资本开支、回款和估值；
- 指出从原路线切换到新路线需要出现的证据。

## Pass（不做）的高价值交付
Pass 不是研究失败。至少输出以下四项：
1. **一剑封喉的死穴证明**：哪 1–2 个关键前提被什么硬证据击穿，证据的边界是什么。
2. **反 FOMO 护盾**：拆解市场最诱人的伪叙事，说明它为何不能推出目标公司的收入、利润或现金流。
3. **外溢副产品资产**：记录本次研究摸清的产业价格底牌、采购/成本机制、可复用技术认知，或邻近替代方向。
4. **复活触发器清单**：列出什么新产品、客户、订单、价格、成本、政策或现金流变化会使方向重新值得研究，并同步写入项目 memory.md 的负知识/等待雷达相应位置。

## 写作要求
先给判断，再给证据和机制。明确区分事实、推断、假设和未知。少写研究过程，多写决策信息。不要把问题图内部编号、状态词和未经验证的路线图直接带入商业正文。禁止无来源数据、伪精确估值和没有依据的仓位建议。
