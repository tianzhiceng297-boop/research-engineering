
# 当前基线

更新时间：2026-09-19

## 现在处于哪里

资产重整已经完成一轮。当前阶段不是继续扩充分类，而是把已经形成的系统放进真实项目运行。

当前结构固定为三个主要内容层：

1. **系统**：当前正在使用的正式研究系统。
2. **理论资产**：尚未进入正式系统的理论与设计探索。
3. **项目**：真实研究任务的运行现场。

Git 负责保存这些对象的修改历史，不再通过单独的“历史”或“版本”目录复制系统文件。

## 当前项目

第一条运行验收线路：

`项目/CQD短波红外/`

验收重点是：

- 材料能否正确进入；
- 问题能否展开并保持可追溯；
- 判断能否回到证据与未知；
- 研究结果能否进入交付；
- 修订和更新能否被记录；
- 项目经验能否与通用系统保持边界。

## 内容状态

进入仓库的具体资产可以处于：

- **正式**：当前可作为默认依据；
- **试用**：用途明确，但仍在验证；
- **停用**：不再作为当前依据，但保留在 Git 历史或必要的项目记录中；
- **待处理**：尚未判断去留。

正式不等于永久正确。正式资产发生结构性修改时，应说明修改原因和影响。

## 版本规则

不通过复制目录管理版本。

- Git 提交记录保存日常修改；
- 需要固定完整状态时，以对应提交作为版本依据；
- 需要对外或给 Agent 交付时，再从指定提交导出完整包；
- 不在仓库里长期维护同一套系统的多份副本。

## 当前仍待验证的问题

- 系统规则的触发条件是否足够清楚；
- 各步骤输入、输出和依赖是否稳定；
- Agent 在缺少口头上下文时能否正确执行；
- 项目经验如何可靠地升级为系统规则；
- 研究更新如何保持完整版本与增量更新之间的可追溯关系。
