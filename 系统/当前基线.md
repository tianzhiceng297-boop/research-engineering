# 当前基线

更新时间：2026-09-18

## 现在处于哪里

资产重整已经完成一轮。接下来的重点是验证这些资产能否在真实研究任务中被正确调用，而不是继续扩大分类体系。

当前基线只固定三件事：

1. GitHub 仓库是研究工程的版本记录与协作底座。
2. CQD 短波红外项目是第一条运行验收线路。
3. 未经真实项目验证的规则、模板和方法，暂不视为稳定能力。

## 资产状态

进入仓库的内容按使用状态区分：

- **正式**：已经在真实任务中使用并通过检查，可作为后续工作的默认依据。
- **试用**：用途明确，但仍需在项目中验证或修改。
- **历史**：不再作为当前依据，但保留用于追溯。
- **待处理**：尚未判断去留，不能被流程默认调用。

“正式”表示当前可用，不表示永久正确。正式资产发生修改时，需要说明修改对象、原因和影响。

## 当前缺口

目前已经有大量研究材料和规则，但还没有充分验证：

- 触发条件是否清楚；
- 每一步需要什么输入、产生什么输出；
- 不同资产之间的依赖是否稳定；
- WorkBuddy、Codex 或其他 Agent 能否在缺少口头上下文时正确执行；
- 交付检查能否发现事实、结构、语言和版本问题；
- 项目更新能否只交付变化部分，同时保持与完整研究包的关系可追溯。

这些缺口由项目运行暴露和修正，不先靠增加术语解决。

## 版本规则

- 结构和核心判断首次稳定时，形成完整版本。
- 局部事实、数据、判断或文字变化，形成增量更新。
- 问题结构、结论框架或交付用途明显改变时，形成新的完整版本。
- 每次提交说明“为什么改”，避免只写“更新文件”。
