# 06｜问题图与研究交付接口

## 一、用途

本文件规定：

> **问题图中的研究结果如何进入正式研究交付体系。**

它不负责定义问题图，也不负责决定研究应该问什么。

它只连接：

> 问题层 → 研究结果 → 交付层

## 二、三层职责

### 问题图

回答：

> 研究什么？

### Agent执行协议

回答：

> 如何管理研究问题？

### 交付体系

回答：

> 研究完成后如何组织、压缩和呈现？

三者必须保持边界。

## 三、什么时候进入交付

一个问题并不是一旦得到答案就必须进入报告。

通常需要同时考虑：

- 当前是否已经形成可用判断；
- 核心事实是否有足够可靠的证据；
- 主要反证是否已经检查；
- 最大的不确定性是否已经明确；
- 继续研究是否还有明显边际价值；
- 该答案是否会影响投资判断或行动。

## 四、交付不是问题图的复制品

问题图可能是：

> 场景 → 性能 → 技术 → 制造 → 成本 → 价格 → 客户 → 公司价值 → 估值

正式交付可能重新组织成：

> 当前判断 → 为什么成立 → 核心证据 → 核心风险 → 为什么是现在 → 接下来观察什么

因此：

> **交付不是问题图的摘要，而是问题图经过研究和判断后的重新编排。**

## 五、从问题图到交付的压缩过程

### 第一步：识别闭合问题

哪些问题已经形成可以使用的答案？

### 第二步：识别关键依赖关系

哪些问题之间的关系真正决定当前判断？

### 第三步：识别汇合点

哪些不同问题链共同支撑一个判断？

### 第四步：识别关键反证

什么证据最可能改变当前判断？

### 第五步：重新组织叙事

把问题图中的研究结构重新组织成面向读者的判断结构。

### 第六步：进入正式交付

根据既有研究交付体系生成：

- 核心结论；
- 主报告；
- 路演/访谈问题；
- 更新记录；
- 研究包；
- 其他正式研究材料。

## 六、哪些内容通常不进入正式交付

一般不直接呈现：

- AI展开的全部候选问题；
- 已停掉的枝；
- 与判断无关的搜索过程；
- 已经纠正的错误路径；
- 大量没有作用的备选解释；
- 问题图内部编号。

但如果某段历史探索本身有解释价值，可以按交付需求重新组织后使用。

## 七、哪些内容应保留在研究资产中但不必进入交付

包括：

- 被放弃的假设；
- 被证伪的路线；
- 无效搜索；
- 暂时不值得继续的问题；
- 未来可能重新打开的方向。

这些内容主要进入05｜探索记忆。

## 八、正式交付最优先保留什么

### 1. 关键事实

发生了什么。

### 2. 关键判断

为什么重要。

### 3. 关键因果关系

为什么这些事实能够支撑这个判断。

### 4. 关键时点

为什么现在重要。

### 5. 关键不确定性

现在还不知道什么。

### 6. 关键跟踪信号

下一次出现什么证据，判断应该更新。

## 九、访谈、尽调、客户验证和跟踪

这些可以理解为问题图在不同阶段产生的行动问题。

例如：

> 桌面研究无法验证 → 形成企业访谈问题；

> 企业无法验证 → 形成客户验证问题；

> 当前判断暂时足够 → 形成跟踪信号；

> 关键估值条件尚未出现 → 形成里程碑观察问题。

具体模板和交付格式由既有交付体系管理，不由02｜问题图本体管理。

## 十、最小输出接口

一个完成研究的高价值问题节点，至少应能够向交付体系提供：

```
问题
当前答案
关键证据
关键反证
关键未知
问题关系
当前判断影响
后续跟踪条件
```

06负责把这些研究结果重新组织成正式交付，不要求保留原问题图结构。

## 十一、交付完成后的回写

正式交付完成后，如果出现：

- 新判断；
- 新证据；
- 新反证；
- 新投资条件；
- 新跟踪指标；
- 新问题；

应回写04｜项目问题图。

如果其中形成了长期可复用经验，应进一步进入05｜探索记忆。

如果某条经验已经经过多个项目验证，可以提交01、02或03的规则升级评估。

## 十二、最终边界

问题图不能为了方便交付而改变问题本身。

交付模板也不能反过来规定研究必须问什么。

如果正式交付需要一个尚未覆盖的问题，应回到问题图新增或修正问题，而不是在报告中临时制造一个脱离研究结构的问题。

核心关系保持为：

> **问题图负责研究问题；研究完成后，交付体系负责重新组织和压缩研究结果。**
